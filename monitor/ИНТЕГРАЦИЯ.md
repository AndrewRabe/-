# Мониторинг цен Ozon в «Домашнем реестре»

Программа мониторинга цен живёт здесь же, в репозитории, и умеет складывать
результаты прямо в реестр: в разделе «Желания» видно текущую цену, минимум и
дату последней проверки. Уведомления в Telegram работают как раньше.

Проверять цены можно двумя способами — они не мешают друг другу.

## Вариант 1. В облаке, по расписанию (компьютер не нужен)

Проверку запускает GitHub Actions каждые 6 часов (`.github/workflows/prices.yml`).

Настройка один раз:

1. Settings репозитория → *Secrets and variables* → **Actions** → *New repository secret*:
   - `YANDEX_TOKEN` — тот же токен Яндекс Диска, что вы вводили в приложении (⚙ → «Шаг 2»);
   - `OZON_TG_TOKEN` и `OZON_TG_CHAT_ID` — если хотите уведомления в Telegram (необязательно).
2. Вкладка Actions → «Проверка цен Ozon» → *Run workflow* — первая проверка вручную.

Важно и честно: Ozon недолюбливает запросы из дата-центров, а серверы GitHub —
как раз оттуда. Возможен ответ 403 или капча; тогда в логе запуска будет
«не вышло получить цену», а в приложении у желания — «монитор: не смог проверить».
В этом случае работает вариант 2.

## Вариант 2. На своём компьютере

```
cd monitor
pip install requests
set YANDEX_TOKEN=…            # Windows;  на macOS/Linux: export YANDEX_TOKEN=…
python registry_sync.py       # проверить и записать в реестр
python registry_sync.py --dry-run   # только показать, ничего не менять
```

Запускать можно по расписанию (Планировщик задач Windows или cron) — данные
попадут в реестр так же, как из облака.

Прежний режим программы (`monitor.py add/run/watch` со своей базой SQLite)
никуда не делся и работает независимо: см. `README.md`.

## Как это устроено

- Список желаний монитор читает из папки приложения на Яндекс Диске (`app:/sync`) —
  туда его пишет сам реестр. Ничего вводить дважды не нужно.
- Результаты пишутся в `app:/prices/<id желания>` (свойства файла: цена, минимум,
  дата, вид цены, наличие). Реестр читает их при открытии раздела «Желания»
  и по кнопке «Обновить цены монитора».
- Токен Яндекса ограничен папкой приложения — доступа к остальному Диску нет.

## Напоминания в Telegram (как в календаре Google)

`reminders.py` читает данные реестра с Диска и присылает утром сообщение:
что просрочено, что сегодня, что завтра — задачи (включая периодические),
мероприятия с повторами, напоминания по инструкциям, дни рождения и
подошедшие сроки обслуживания машины. Если дел нет — сообщение не приходит.

Запуск по расписанию: workflow «Напоминания в Telegram»
(`.github/workflows/reminders.yml`), каждый день в 08:00 по Москве.
Нужны те же секреты, что и для цен: `YANDEX_TOKEN`, `OZON_TG_TOKEN`,
`OZON_TG_CHAT_ID`. Время меняется в поле `cron` (оно в UTC), часовой пояс —
переменной `TZ_OFFSET`.

Вручную:

```
cd monitor
YANDEX_TOKEN=… python reminders.py --dry-run   # показать текст
YANDEX_TOKEN=… OZON_TG_TOKEN=… OZON_TG_CHAT_ID=… python reminders.py
```

## Пуш-уведомления на телефон (без Telegram)

Приложение — устанавливаемое (PWA): на Android его можно добавить на главный
экран, и тогда уведомления приходят системно, даже когда оно закрыто.

Как устроено: телефон подписывается у службы пушей браузера, подписка
сохраняется в папку приложения на Диске (`app:/push/<устройство>`), а
`push_send.py` из GitHub Actions читает подписки и шлёт зашифрованные
сообщения. Шифрование (RFC 8291) и подпись VAPID (RFC 8292) реализованы
в `webpush.py` — из зависимостей нужен только `cryptography`.

Настройка один раз:

1. Сгенерируйте пару ключей: `cd monitor && python webpush.py`.
2. Приватный ключ → Settings репозитория → Secrets → Actions → **`VAPID_PRIVATE_KEY`**.
   Публичный ключ уже вписан в `index.html` (переменная `VAPID_PUBLIC`) — если
   генерируете свою пару, замените его там же.
3. По желанию: переменная репозитория `APP_URL` — адрес приложения, чтобы
   нажатие на уведомление открывало нужную страницу.
4. На телефоне: откройте приложение в Chrome → меню → «Добавить на главный
   экран» → запустите с иконки → ⚙ → «Включить пуш-уведомления».

Каждое устройство подключается отдельно. Недействительные подписки (удалённое
приложение, отозванное разрешение) скрипт удаляет сам.

Оговорки: на Android нужен Chrome или другой браузер на его основе; на iPhone
пуши работают только для приложения, добавленного на главный экран, начиная с
iOS 16.4. Если пуши почему-то не дойдут, параллельно работает Telegram.

## Напоминания к назначенному времени

Если у задачи или мероприятия указано время, уведомление приходит именно к нему,
а не только утренней сводкой. Этим занимается `notify_due.py`: workflow
«Напоминания ко времени» запускает его каждые 15 минут, скрипт смотрит,
чему подошёл срок в ближайшем окне, и шлёт пуш и сообщение в Telegram.
Отправленное помечается в `app:/pushlog/<дата>`, поэтому одно и то же
напоминание не приходит дважды; старые отметки удаляются.

В настройках приложения (⚙ → «Напоминать заранее») можно выбрать, за сколько
предупреждать: в назначенное время, за 5, 10, 15, 30 минут или за час.

Честная оговорка про точность: расписание GitHub Actions не гарантирует запуск
секунда в секунду — при большой нагрузке запуск может задержаться на несколько
минут. Обычно уведомление приходит в пределах 15 минут от назначенного времени.

Проверить вручную:

```
cd monitor
YANDEX_TOKEN=… python notify_due.py --dry-run --at 08:00
```

## Синхронизация с Google Календарём (подписка на ленту)

`ics_feed.py` собирает из данных реестра файл `calendar.ics` — задачи со сроком,
мероприятия с повторами и дни рождения, — кладёт его на Яндекс Диск, публикует
и печатает постоянную ссылку. Скрипт запускается вместе с утренними
напоминаниями, так что лента обновляется сама.

Как подписаться:

1. Запустите workflow «Напоминания» (или `python ics_feed.py`) и скопируйте
   ссылку из журнала — она постоянная, менять её потом не нужно.
2. В Google Календаре на компьютере: «Другие календари» → «+» →
   **Подписаться по URL** → вставьте ссылку. В Яндекс Календаре — «Добавить
   календарь» → «По ссылке». На iPhone — Настройки → Календарь → Учётные
   записи → Подписной календарь.
3. Календарь сам подтягивает изменения. Google обновляет внешние ленты
   примерно раз в несколько часов — это его ограничение, ускорить нельзя;
   для срочного добавления есть ручная выгрузка `.ics` из приложения.

Честно про ограничения: подписка **односторонняя** — правки в Google обратно
в реестр не попадают. Ссылка публичная, хотя и с неугадываемым адресом: не
кладите в названия задач то, что не должно попасть к чужим глазам. Отозвать
доступ можно в Яндекс Диске, сняв публикацию с файла `calendar.ics` в папке
приложения.
