# Домашний реестр

Система учёта домашнего имущества в одном HTML-файле (`index.html`). Работает с любого устройства через браузер. Данные хранятся в **вашем** облаке на выбор: Яндекс Диск или приватный GitHub-репозиторий — бесплатно и без сторонних серверов.

## Возможности

- **Разделы**: Жильё 🏠, Машина 🚗, Техника 🔧, Одежда 👕, Вещи 📦.
- **Тип жилья** (в карточке раздела «Жильё»): своё или съёмное. Для съёмного — плата, число платежа, срок договора, залог и контакты собственника, с подсказкой о ближайшем платеже и кнопками «Напоминать о платеже» (создаёт ежемесячную задачу) и «Напомнить о продлении» (за месяц до конца договора). Для своего — площадь, дата покупки, кадастровый номер. Тип виден меткой на карточке.
- **Обслуживание машины** (в карточке раздела «Машина»): текущий пробег, регламент расходников с интервалами по километрам и месяцам (масло, фильтры, тормозная жидкость, антифриз, свечи, ГРМ, ТО, шины, ОСАГО, техосмотр — плюс свои позиции) с полосой износа и статусами «скоро» / «просрочено», отметка «сделано сегодня» с записью в журнал, кнопка «в задачи»; журнал работ и расходов с датой, пробегом, местом и стоимостью, итоговой суммой.
- **Хранение и QR-этикетки**: места с вложенностью (кладовка → коробка), привязка вещи к месту с уточнением (полка, ячейка), список содержимого и счётчики. Кнопка «Печать этикеток с QR» выдаёт лист с кодами: наклеили на коробку, навели камеру телефона — открылся список того, что внутри. Генератор QR лежит в репозитории (`vendor/qrcode.js`), интернет для печати не нужен.
- **Покупка**: у вещей, одежды и техники — цена и дата покупки, ссылка на товар; при продаже видно, сколько выиграли или потеряли против цены покупки (в том числе в общей статистике).
- **Карточка объекта**: фото, заметки, характеристики (модель, серийный номер, гарантия…), задачи, вопросы, планы и покупки, инструкции по ремонту и обслуживанию.
- **Сводки**: весь список задач по всем объектам (открытые сверху, выполненные ниже) и общий список «Покупки и планы» (докупить / улучшить). В сводках можно добавлять и удалять строки, выбирая объект, — списки общие с карточками.
- **Статусы**: «В строю», «На продажу», «Продано», «Архив».
- **Продажи и статистика**: у проданной вещи — цена, дата, площадка, комиссия (в процентах или рублями), доставка и прочие расходы, итог «на руки». Раздел «Продано» показывает показатели за всё время, год или месяц: на руки, сумма продаж, комиссии с долей от суммы, средняя и лучшая продажа, а также сколько сейчас выставлено на продажу; суммы попадают и в CSV из архива объявлений.
- **Календарь**: месячная сетка, в ячейках видны сами записи (строки кликабельны — открывают карточку объекта или раздел с днями рождения) — мероприятия со временем, дни рождения, задачи и напоминания по инструкциям, цветом по типу и счётчиком «+ ещё N»; на телефоне вместо строк компактные точки. Мероприятия умеют повторяться — каждый день, неделю (с выбором дней), месяц или год: работа, тренировки, регулярные встречи заводятся один раз.
- **Отмена действия**: после отметки задачи, переноса периодической задачи, удаления записи или объекта в подсказке внизу появляется «Отменить» / «Вернуть» — состояние восстанавливается целиком.
- **Периодические задачи**: у задачи можно задать повтор (день / неделя / месяц / год) — «полить цветы», «проверить фильтры». Отметка не закрывает такую задачу, а переносит на следующий срок (пропущенные периоды пролистываются); в списках она помечена 🔁.
- **Задачи у инструкций**: к инструкции можно привязать свои задачи — они видны и в самой инструкции, и в общем списке задач с меткой 📘; при удалении инструкции задачи остаются, только теряют метку.
- **Напоминания у инструкций**: у каждой инструкции можно задать дату и повтор (день / неделя / месяц / год) — «чистить фильтр раз в 3 месяца», «поверка счётчиков раз в год». Напоминания видны в календаре, попадают в уведомления, отмечаются одним нажатием (повторяющиеся сами переносятся на следующий срок) и превращаются в задачу.
- **Дни рождения**: отдельный раздел со списком по близости даты, возрастом (если известен год) и метками «сегодня» / «скоро»; попадают в календарь.
- **Импорт**: мероприятия и дни рождения из `.ics` (экспорт Google или Яндекс Календаря, с повторами); задачи из `Tasks.json` Google Takeout — со списками на выбор, привязкой каждого списка к своему объекту, переносом повторяющихся задач в периодические и опцией «переносить выполненные».
- **Подписка календаря**: `monitor/ics_feed.py` публикует ленту `.ics` на Яндекс Диске и выдаёт постоянную ссылку — Google или Яндекс Календарь подписывается на неё и подтягивает изменения сам (в одну сторону, с задержкой обновления на стороне Google).
- **Выгрузка в календарь телефона** (⚙ → Календарь телефона): файл `.ics` с задачами, мероприятиями и днями рождения — напоминания срабатывают локально, секунда в секунду, без интернета. Отдельную задачу выгружает кнопка 📅 в её строке.
- **Напоминания ко времени**: у задачи можно указать не только дату, но и время — уведомление придёт к нему (мероприятия так умели и раньше). Проверка идёт каждые 15 минут, в настройках выбирается, за сколько предупреждать (в срок, за 5–60 минут).
- **Пуш-уведомления на телефон**: приложение устанавливается на главный экран (PWA), подписка хранится в папке приложения на Диске, а GitHub Actions шлёт зашифрованные пуши по расписанию — уведомление приходит, даже когда приложение закрыто. Шифрование и подпись написаны без сторонних библиотек (`monitor/webpush.py`).
- **Напоминания**: в браузере — уведомление при открытии приложения (⚙ → Напоминания); в Telegram — ежедневное сообщение по расписанию (что просрочено, что сегодня и завтра, включая мероприятия, дни рождения и сроки по машине), его шлёт `monitor/reminders.py` из GitHub Actions, телефон при этом не нужен включать. Подробности: [monitor/ИНТЕГРАЦИЯ.md](monitor/ИНТЕГРАЦИЯ.md).
- **Желания**: список покупок с целевой, текущей и минимальной ценой, ссылками на площадки и меткой «цена достигла цели». Цены Ozon проверяет монитор из папки `monitor/` — в облаке по расписанию (GitHub Actions) или на вашем компьютере — и складывает их обратно в реестр; уведомления приходят в Telegram. Подробности: [monitor/ИНТЕГРАЦИЯ.md](monitor/ИНТЕГРАЦИЯ.md).
- **Объявления и продажа**: для вещей «На продажу» — поля объявления (состояние, комплект, недостатки, способы передачи…), генератор текста для Авито/Юлы (кратко/подробно) с лимитами, проверками (телефон в тексте, CAPS, нет фото…) и копированием в один клик; отметки «где выложено» со ссылкой и счётчиком дней.
- **Архив объявлений** (ZIP): папка на каждую вещь с фото по порядку и текстами `avito.txt` / `youla.txt`, страница `Объявления.html` с кнопками «копировать», таблица `Список вещей.csv`, по желанию фиды `avito-feed.xml` и `youla-feed.yml`, инструкция `Как выкладывать.txt`.
- **Поиск** по названиям, заметкам и характеристикам.
- **Резервная копия**: экспорт данных одним файлом; «Восстановить из файла» заменяет всё содержимое, «Добавить из копии» дописывает записи к текущим без потерь (объекты сливаются по названию, дубли задач, мероприятий и желаний не создаются).

## Как всё устроено

- Само приложение — статичная страница, публикуется на **GitHub Pages** (workflow `.github/workflows/pages.yml`, автоматически при каждом пуше).
- Хранилище данных выбирается в настройках (⚙):
  - **Яндекс Диск** — вход по кнопке через Яндекс-аккаунт (OAuth). Данные (`state.json`) и фото лежат в папке приложения на вашем Диске (`Приложения/…`); приложение видит только эту папку, весь остальной Диск ему недоступен.
  - **GitHub** — данные и фото сохраняются через GitHub API в отдельный приватный репозиторий по fine-grained-токену.
- Токены хранятся только в браузере устройства (localStorage) и никуда, кроме API выбранного сервиса, не отправляются.
- Без настройки синхронизации приложение работает автономно на одном устройстве.
- При одновременных изменениях с двух устройств побеждает более новая версия; изменения подтягиваются при возврате на вкладку.

## Настройка: Яндекс Диск (рекомендуется, ~5 минут)

1. Откройте **oauth.yandex.ru** → «Создать приложение»:
   - название любое, например «Домашний реестр»;
   - доступ к данным: **Доступ к папке приложения на Диске** (`cloud_api:disk.app_folder`);
   - Redirect URI менять не нужно — оставьте предложенный Яндексом (`verification_code`).
2. Скопируйте **ClientID** созданного приложения.
3. В приложении: ⚙ → вкладка «Яндекс Диск» → вставьте ClientID → «Шаг 1: получить токен» → подтвердите доступ. Яндекс покажет страницу с токеном.
4. Скопируйте токен (или весь адрес страницы) → вставьте в поле «Шаг 2» → «Подключить».
5. На остальных устройствах повторите шаги 3–4 (ClientID тот же). На телефоне удобно добавить страницу на главный экран.

Токен Яндекса живёт около года; когда истечёт — приложение попросит получить его заново.

## Настройка: GitHub (альтернатива)

1. Создайте приватный репозиторий `home-registry-data` (github.com → «+» → New repository → Private).
2. Settings профиля → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate:
   *Repository access*: Only select repositories → `home-registry-data`; *Permissions* → Contents: **Read and write**.
3. В приложении: ⚙ → вкладка «GitHub» → логин, репозиторий, токен → «Проверить и сохранить».

## Включение GitHub Pages (хостинг страницы)

Workflow пытается включить Pages автоматически, но у встроенного токена Actions обычно нет на это прав. Включите вручную один раз: Settings репозитория → **Pages** → *Build and deployment* → Source: **GitHub Actions**, затем вкладка Actions → «Публикация на GitHub Pages» → *Re-run all jobs*. Адрес сайта появится в результатах workflow.

## Безопасность

- Код приложения публичный, данные — нет: они лежат в папке приложения вашего Диска или в приватном репозитории.
- Токен Яндекса ограничен папкой приложения; токен GitHub — одним репозиторием и только содержимым файлов.
- Экспорт (⚙) позволяет в любой момент забрать все данные одним файлом и переехать куда угодно.
